# AHP 입지적합도 사용설명서

이 문서는 ArchToolkit의 `AHP 입지적합도 (AHP Suitability)` 도구가 **실제로 무엇을 계산하는지** 설명합니다.
일반적인 AHP 교과서 설명이 아니라, 이 플러그인 코드(`tools/ahp_core.py`, `tools/ahp_suitability_dialog.py`)가
수행하는 연산을 그대로 기술합니다. 문서의 모든 수치 예시는 실제 코드를 실행해 얻은 값입니다.

---

## 1. 이 도구가 푸는 문제

여러 환경 래스터(경사, 하천까지 거리, 지질, 일사 등)를 하나의 **적합도 지도**로 합치고 싶습니다.
합치려면 두 가지를 정해야 합니다.

1. **각 변수 안에서**: 이 값은 좋은가 나쁜가? (경사 5도와 35도 중 어느 쪽이 유적 입지에 유리한가)
2. **변수들 사이에서**: 어느 변수가 더 중요한가? (경사가 하천 거리보다 얼마나 더 중요한가)

1번은 **채점(scoring)**, 2번은 **가중치(weighting)** 입니다. AHP는 2번을 푸는 방법이고,
이 도구는 1번을 위해 다섯 가지 채점 모드를 따로 제공합니다.

최종 계산은 단순합니다:

```
적합도 = Σ ( 변수ᵢ의 점수(0-1) × 변수ᵢ의 가중치 )
```

가중치의 합이 1이므로 적합도도 0-1 범위입니다(`0-100` 체크 시 100을 곱합니다).

### AHP가 왜 필요한가

"경사 50%, 하천 30%, 지질 20%"처럼 가중치를 직접 적는 게 더 쉬워 보입니다. 실제로 그래도 됩니다.
AHP가 주는 것은 두 가지뿐입니다.

- **한 번에 두 개만 비교하면 됩니다.** 변수가 6개일 때 "각각 몇 %"를 한 번에 정하는 것보다,
  "경사 vs 하천"을 15번 답하는 쪽이 사람에게 훨씬 쉽고 일관됩니다.
- **모순을 잡아줍니다.** 일관성비율(CR)이 그 역할입니다(5장).

AHP는 **당신의 판단을 숫자로 옮기는 장치**이지, 판단을 대신 내려주지 않습니다.
가중치가 근거를 갖는지는 전적으로 사용자의 몫입니다.

## 2. 전체 흐름

```
1. 기준(변수) 래스터 추가        ← 경사, 거리, 지질 …
2. 각 기준의 채점 방식 지정       ← benefit / cost / target / range / reclass
3. 통계 계산 (min/max)          ← 채점 램프의 양 끝점
4. 쌍대비교 입력                 ← "A가 B보다 몇 배 중요한가"
5. CR 확인                      ← 권장 ≤ 0.10
6. 실행                         ← 가중합 래스터 출력
```

3번을 건너뛰면 실행 시 `min/max 통계가 없습니다` 오류가 납니다. 채점 램프의 끝점을 모르면
점수를 만들 수 없기 때문입니다.

---

## 3. 채점 모드 — 변수 하나를 0-1로 바꾸기

각 기준 행에서 방식을 고릅니다. 아래는 **경사도 0-40도**를 실제로 각 모드에 넣어 얻은 점수입니다.

| 경사도 | 0 | 5 | 10 | 15 | 20 | 25 | 30 | 35 | 40 |
|---|---|---|---|---|---|---|---|---|---|
| **benefit** 클수록 좋음 | 0.00 | 0.12 | 0.25 | 0.38 | 0.50 | 0.62 | 0.75 | 0.88 | 1.00 |
| **cost** 작을수록 좋음 | 1.00 | 0.88 | 0.75 | 0.62 | 0.50 | 0.38 | 0.25 | 0.12 | 0.00 |
| **target** 10도가 최적 | 0.00 | 0.50 | **1.00** | 0.83 | 0.67 | 0.50 | 0.33 | 0.17 | 0.00 |
| **range** 5-15도 선호 | 0.00 | **1.00** | **1.00** | **1.00** | 0.80 | 0.60 | 0.40 | 0.20 | 0.00 |
| **reclass** 구간 점수표 | 1.00 | 1.00 | 0.60 | 0.60 | 0.20 | 0.20 | 0.00 | 0.00 | 0.00 |

### 언제 무엇을 쓰나

- **cost** — 하천까지 거리, 기존 유적까지 거리. 가까울수록 좋다면 이것입니다.
- **benefit** — 조망 범위, 누적 가시권. 클수록 좋다면.
- **target** — "최적값이 중간에 있는" 변수. 예: 경사 8도 전후가 가장 좋고 너무 평탄해도(침수) 너무 급해도 나쁨.
  최적값에서 1.0, min/max 양쪽으로 직선 하강합니다.
- **range** — 최적이 **구간**인 경우. 예: 해발 50-120 m가 모두 동등하게 좋음.
  구간 안은 전부 1.0, 바깥으로 직선 하강합니다.
- **reclass** — **범주형 변수 전용**. 지질 단위, 토지피복처럼 코드값에 순서가 없는 경우.
  구간별로 점수를 직접 지정합니다.

### reclass 주의점 두 가지

**경계값은 위쪽 구간에 속합니다.** `[0,10]=1.0`, `[10,20]=0.6`으로 지정하면
경사 정확히 10은 **0.6**입니다(표에서 확인 가능). 마지막 구간만 `<=`로 닫히고 나머지는 `<`입니다.

**구간이 겹치면 실행이 막힙니다.** `구간 점수표에 서로 겹치는 구간이 있습니다` 오류가 납니다.
이건 의도된 동작입니다 — 겹치면 점수가 더해져 1을 넘습니다.

### 범주형에는 반드시 reclass를 쓰세요

지질 코드가 1, 2, 3 … 14라고 할 때 `benefit`을 쓰면 "코드 14가 코드 1보다 14배 좋다"는
의미가 됩니다. 코드 번호는 순서가 아니므로 완전히 틀린 해석입니다. reclass로 각 지질 단위에
점수를 직접 주세요. (도구는 reclass 기준을 자동으로 **최근접 리샘플링**해서 코드가
섞이지 않게 합니다.)

## 4. 쌍대비교 입력 — 가중치 정하기

표의 각 칸에 "행이 열보다 몇 배 중요한가"를 넣습니다. 쓸 수 있는 값은 Saaty 척도입니다:

| 값 | 의미 |
|---|---|
| 1 | 두 변수가 똑같이 중요 |
| 3 | 행이 열보다 **약간** 더 중요 |
| 5 | 행이 열보다 **뚜렷하게** 더 중요 |
| 7 | 행이 열보다 **매우** 더 중요 |
| 9 | 행이 열보다 **극단적으로** 더 중요 |
| 2, 4, 6, 8 | 위 단계들의 중간 |
| 1/3, 1/5 … | 반대 방향 (열이 행보다 중요) |

**아래 삼각형은 자동으로 채워집니다.** `경사 vs 하천 = 3`을 넣으면 `하천 vs 경사`는 자동으로 1/3이 됩니다.
위 삼각형만 채우면 됩니다. 변수가 n개면 입력할 칸은 n(n-1)/2개입니다 (4개면 6칸, 6개면 15칸).

### 실제 계산 결과

변수 4개(경사, 하천거리, 지질, 일사)에 대해 실제로 돌린 결과입니다.

**의도적으로 완전히 일관되게 넣은 경우** (경사:하천:지질:일사 = 8:4:2:1 의도)

```
경사 vs 하천=2,  경사 vs 지질=4,  경사 vs 일사=8
             하천 vs 지질=2,  하천 vs 일사=4
                            지질 vs 일사=2
→ 경사 53.3%  하천 26.7%  지질 13.3%  일사 6.7%     CR = 0.000
```

**현실적인 전문가 입력** (딱 떨어지지 않게)

```
경사 vs 하천=2,  경사 vs 지질=5,  경사 vs 일사=7
             하천 vs 지질=3,  하천 vs 일사=5
                            지질 vs 일사=2
→ 경사 52.7%  하천 30.1%  지질 11.0%  일사 6.3%     CR = 0.007
```

CR이 0.007이면 훌륭합니다. 실무에서는 이 정도면 충분합니다.

**아무것도 입력하지 않으면** 모든 칸이 1이고 결과는 **균등 가중치(각 25%)** 입니다.
CR은 0.000으로 나오지만 이건 "일관적"이 아니라 "아무 판단도 하지 않았다"는 뜻입니다.
CR만 보고 안심하면 안 되는 이유입니다.

## 5. CR (일관성비율) — 가장 오해받는 숫자

### CR이 잡아내는 것

CR은 **당신의 판단이 서로 모순되는 정도**입니다. 정확성이 아니라 **내부 일관성**만 봅니다.

전형적인 모순은 순환 선호입니다. 실제로 돌려본 예:

```
경사 vs 하천 = 5    (경사가 훨씬 중요)
하천 vs 지질 = 5    (하천이 훨씬 중요)
경사 vs 지질 = 1/5  (그런데 지질이 경사보다 훨씬 중요?)

→ 경사 31.5%  하천 31.5%  지질 31.5%  일사 5.5%     CR = 1.009
```

CR 1.009는 기준 0.10의 **10배**입니다. 그리고 결과를 보세요 — 세 변수가 31.5%로 똑같이 나왔습니다.
모순된 입력을 억지로 평균 낸 결과이고, **아무 의미가 없습니다.** CR이 없었다면 이 지도를
그럴듯하게 받아들였을 겁니다.

### 기준

- **CR ≤ 0.10** — 권장 (Saaty 1980). 이대로 쓰세요.
- **0.10 < CR ≤ 0.20** — 재검토 권장. 실행은 되지만 경고가 뜹니다.
- **CR > 0.20** — 어딘가 모순이 있습니다. 반드시 고치세요.

도구는 CR이 높아도 **막지 않고 경고만** 합니다(`AHP 일관성비율(CR)이 높습니다`).
판단은 사용자 몫이라는 설계입니다.

### CR이 높을 때 고치는 법

1. **가장 큰 값(9, 1/9)부터 의심하세요.** 극단값이 모순을 만드는 주범입니다.
2. **암묵적 순위를 먼저 적어보세요.** "경사 > 하천 > 지질 > 일사"를 종이에 쓰고,
   그 순위와 어긋나는 칸을 찾으세요.
3. **비율을 대략 맞추세요.** 경사가 지질보다 4배 중요하고 지질이 일사보다 2배 중요하면,
   경사 vs 일사는 8 근처여야 합니다. 3이나 9를 넣으면 모순이 커집니다.

### CR이 계산되지 않는 경우

- 기준이 **2개 이하**면 CR은 정의상 0입니다 (모순이 불가능).
- 기준이 **15개를 넘으면** CR이 `-`로 표시됩니다. Saaty의 무작위지수(RI) 표가 15까지만
  있기 때문이고, 이 도구는 그 바깥에서 0.0을 찍어 "일관적"이라고 거짓말하는 대신
  정직하게 미정의로 둡니다. **기준 15개가 넘어가면 계층형(6장)을 쓰세요.**

## 6. 계층형 AHP — 기준이 많을 때

기준이 7개를 넘으면 쌍대비교가 21칸 이상이 되어 사람이 일관성을 유지하기 어렵습니다.
계층형은 기준을 **상위 그룹**으로 묶습니다.

```
지형          (그룹 가중치 0.6)
  ├ 경사       (그룹 내 0.5)  → 최종 0.30
  └ TPI        (그룹 내 0.5)  → 최종 0.30
수문·자원      (그룹 가중치 0.4)
  ├ 하천거리   (그룹 내 0.75) → 최종 0.30
  └ 지질       (그룹 내 0.25) → 최종 0.10
```

**최종 가중치 = 그룹 가중치 × 그룹 내 가중치**, 그 뒤 합이 1이 되도록 정규화합니다.

비교 횟수가 크게 줍니다. 기준 6개를 3그룹으로 묶으면 그룹 간 3칸 + 각 그룹 내 1칸씩 = 6칸으로,
평면형의 15칸보다 훨씬 적습니다. **CR도 그룹별로 따로** 계산되므로 어디서 모순이 났는지 좁혀집니다.

계층형으로 정한 가중치는 평면 쌍대비교 표에 **비율로 역산되어 채워집니다**. 표를 열어보면
계층 계산 결과가 반영돼 있고, 그 뒤 손으로 미세조정할 수 있습니다.

## 7. min/max 통계와 AOI — 결과가 바뀌는 지점

`통계 계산` 버튼은 각 래스터의 최소/최대를 읽어 채점 램프의 양 끝점으로 씁니다.
**이게 결과를 크게 바꿉니다.**

`AOI 범위로 자르기`가 켜져 있으면 통계는 **AOI 안에서만** 계산됩니다.
전국 DEM을 쓰면서 조사구역만 보고 싶다면 반드시 켜세요. 끄면 백두산 고도가 max가 되어
조사구역 전체가 0점 근처로 뭉갭니다.

> **핵심**: min/max가 바뀌면 같은 입력, 같은 가중치라도 적합도 지도가 달라집니다.
> 두 지역을 비교하려면 min/max를 통일해야 합니다. 서로 다른 AOI에서 각각 통계를 낸
> 두 지도는 **직접 비교할 수 없습니다.**

`기준 격자에 정렬`은 입력 래스터들의 CRS·해상도·범위가 다를 때 하나로 맞춥니다.
연속형은 이중선형, reclass(범주형)는 자동으로 최근접을 씁니다.

## 8. 결과 해석

출력은 0-1(또는 0-100) 래스터입니다. 레이어 메타데이터에 `kind=suitability`,
가중치와 CR이 `params_json`으로 붙습니다.

**적합도 값은 확률이 아닙니다.** 0.8은 "유적이 있을 확률 80%"가 아니라
"당신이 정한 기준과 가중치에서 상대적으로 높은 점수"입니다. 절대적 의미가 없으므로
임계값(예: 0.7 이상을 고적합)은 데이터가 아니라 **판단**으로 정해야 합니다.

### 반드시 알아야 할 한계

AHP 적합도는 **가설이지 검증된 모델이 아닙니다.** 기존 유적 분포로 검증한 적이 없습니다.
가중치는 전문가 판단이고, 그 판단이 맞는지는 이 도구가 알려주지 않습니다.
CR이 0.00이어도 가중치가 현실과 동떨어져 있을 수 있습니다 — CR은 일관성만 보지
타당성은 보지 않습니다.

검증하려면 기존 유적 위치를 적합도 지도에 올려 실제로 고적합 구역에 몰리는지 확인하세요.
정량적 검증이 필요하면 통계 모델(MaxEnt/GLM/RF 등)을 쓰는 것이 맞습니다.

### 예측모델의 입력 변수로 쓰지 마세요

AHP 적합도 래스터를 통계 예측모델의 **예측변수로 투입하면 순환 논증**이 됩니다.
적합도는 이미 경사·거리·지질의 가중합이고, 그 가중치는 "유적이 어디 있는지"에 대한
사전 판단이 들어간 값입니다. 그걸 다시 유적 분포로 학습시키면 모델은
자기 자신을 예측하게 됩니다.

예측모델에는 **원재료 변수(경사, 거리, 지질)를 직접** 넣으세요.
AHP 적합도는 모델의 **비교 대상**이나 **조사 우선순위 지도**로 쓰는 것이 올바른 용법입니다.

## 9. 실전 예시 — 청동기 취락 입지

**가설**: 완만한 남향 사면, 하천 접근이 좋고, 급경사가 아닌 곳.

**기준 설정**

| 기준 | 모드 | 설정 | 이유 |
|---|---|---|---|
| 경사도 | `target` | 최적 8도 | 너무 평탄=침수, 너무 급함=거주 불가 |
| 하천까지 거리 | `cost` | — | 가까울수록 좋음 |
| TRASP (일사) | `benefit` | — | 값이 클수록 남향·건조 |
| 지질 | `reclass` | 충적층 1.0, 단구 0.8, 기반암 0.2 | 코드값에 순서 없음 |

**쌍대비교**

```
              경사   하천   일사   지질
경사           1      2      5      4
하천                  1      3      3
일사                         1      1
지질                                1
```

**결과** (실제 계산): 경사 50.2%, 하천 29.0%, 지질 10.7%, 일사 10.1%, λmax = 4.0155, **CR = 0.006** → 사용 가능.

**실행 전 점검**
- `AOI 범위로 자르기` 켜기 (조사구역 기준 통계)
- `통계 계산` 누르기
- 지질이 `reclass`인지 확인 (benefit이면 완전히 틀립니다)
- CR 확인

## 부록 — 계산 내부

관심 있는 분을 위한 요약입니다. 구현은 `tools/ahp_core.py`에 있고 `tests/test_ahp_core.py`로 검증됩니다.

1. **쌍대비교 행렬** `M`을 만듭니다. `M[i][j] = 값`, `M[j][i] = 1/값`, 대각선은 1.
   입력값은 [1/9, 9]로 제한됩니다.
2. **가중치**는 `M`의 **주고유벡터**입니다 (`np.linalg.eig`에서 최대 고유값에 대응하는 벡터의
   절댓값을 합이 1이 되도록 정규화). 행별 평균 같은 근사가 아니라 정식 고유벡터 해법입니다.
3. **일관성지수** `CI = (λmax − n) / (n − 1)`. 완전히 일관되면 `λmax = n`이라 `CI = 0`입니다.
4. **일관성비율** `CR = CI / RI(n)`. `RI`는 같은 크기 무작위 행렬의 평균 CI로,
   n = 1-15까지 표로 들어 있습니다. 표 밖이면 `NaN`(화면에 `-`)입니다.
5. **점수식**은 gdal_calc 표현식 문자열로 생성되어 `minimum(maximum(…, 0), 1)`로 감싸집니다.
   통계 범위 밖 픽셀이 있어도 점수가 0-1을 벗어나지 않습니다.
6. **가중합**은 기준마다 `점수 × 가중치` 래스터를 만든 뒤 순차적으로 더합니다.
